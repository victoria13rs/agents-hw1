# Proposal: add-weekly-tracker

## Why

Нужен простой автономный мини-трекер учебных задач на неделю. Он показывает, сколько часов запланировано, сколько уже выполнено и какой процент работы сделан. Трекер должен работать без сети, без CDN, без внешних библиотек и без API-ключей.

## What Changes

- Добавляется мини-трекер задач. У каждой задачи есть поля `id`, `title`, `hours`, `done`.
- При первом запуске загружается стартовый пример: «Чтение» (2 ч, выполнено), «Практика» (4 ч, не выполнено), «Повторение» (2 ч, не выполнено).
- Пользователь может добавить задачу, удалить задачу и переключить у нее отметку выполнения. Каждое из этих действий меняет данные, а не только внешний вид.
- При добавлении проверяются название и часы. Ошибка показывается рядом с полем, а введенные значения остаются в форме.
- Показываются общая сумма часов, сумма выполненных часов и прогресс в процентах. Все три величины считаются по всем задачам.
- Фильтр меняет только видимый список и не влияет на итоги.
- Интерфейс читается на ширине 390 px без горизонтального скролла, у всех полей и кнопок есть подписи.
- Необязательное улучшение: задачи сохраняются в localStorage. Если хранилище недоступно, показывается понятное сообщение, а трекер продолжает работать в памяти.

## Scope

Поставка возможна в одном из двух вариантов:

- **A:** один файл `tracker-v2.html`, CSS и JavaScript встроены в него.
- **B:** `index.html`, `styles.css`, `app.mjs` (интерфейс), `domain.mjs` (данные и расчеты), `tests/acceptance.test.mjs` (приемочные тесты логики).

## Non-Goals

- Сервер, синхронизация, учетные записи, сеть.
- Внешние библиотеки, фреймворки, CDN, сборщики, API-ключи.
- Редактирование названия или часов у существующей задачи, сроки, приоритеты, категории, несколько недель.
- Любые функции, которых нет в постановке.

## Impact

- Новая возможность: `tracker` (см. `specs/tracker/spec.md`).
- Существующий код не затрагивается.
- Спецификация и реализация выполняются разными запросами. На этапе спецификации код не пишется.
