````markdown
# Proposal: add-weekly-tracker

## Why

Нужен простой автономный мини-трекер учебных задач на неделю. Он показывает, сколько часов запланировано, сколько уже выполнено и какой процент работы сделан. Трекер должен работать без сети, без CDN, без внешних библиотек и без API-ключей.

## What Changes

- Добавляется мини-трекер задач. У каждой задачи есть поля `id`, `title`, `hours`, `done`.
- При первом запуске загружается стартовый пример: «Чтение» (2 ч, выполнено), «Практика» (4 ч, не выполнено), «Повторение» (2 ч, не выполнено).
- Пользователь может добавить задачу, удалить задачу и переключить у нее отметку выполнения. Каждое из этих действий меняет данные, а не только внешний вид.
- При добавлении проверяются название и часы. Ошибка показывается рядом с полем, а введенные значения остаются в форме.
- Показываются общая сумма часов, сумма выполненных часов и прогресс в процентах. Все три величины считаются по всем задачам.
- Фильтр меняет только видимый список и не влияет на итоги.
- Интерфейс читается на ширине 390 px без горизонтального скролла, у всех полей и кнопок есть подписи.
- Необязательное улучшение: задачи сохраняются в localStorage. Если хранилище недоступно, показывается понятное сообщение, а трекер продолжает работать в памяти.

## Scope

Поставка возможна в одном из двух вариантов:

- **A:** один файл `tracker-v2.html`, CSS и JavaScript встроены в него.
- **B:** `index.html`, `styles.css`, `app.mjs` (интерфейс), `domain.mjs` (данные и расчеты), `tests/acceptance.test.mjs` (приемочные тесты логики).

## Non-Goals

- Сервер, синхронизация, учетные записи, сеть.
- Внешние библиотеки, фреймворки, CDN, сборщики, API-ключи.
- Редактирование названия или часов у существующей задачи, сроки, приоритеты, категории, несколько недель.
- Любые функции, которых нет в постановке.

## Impact

- Новая возможность: `tracker` (см. `specs/tracker/spec.md`).
- Существующий код не затрагивается.
- Спецификация и реализация выполняются разными запросами. На этапе спецификации код не пишется.
````

````markdown
# Spec delta: tracker

## ADDED Requirements

### Requirement: Модель задачи и стартовые данные

Каждая задача MUST иметь поля `id` (уникальный в списке), `title` (строка), `hours` (число), `done` (логическое значение).
Если сохраненных данных нет, трекер MUST стартовать со списком: «Чтение» — 2 ч, `done=true`; «Практика» — 4 ч, `done=false`; «Повторение» — 2 ч, `done=false`.

#### Scenario: Итоги стартового примера
- **WHEN** трекер открыт со стартовым примером
- **THEN** всего показано 8 ч, выполнено 2 ч, прогресс 25%

### Requirement: Добавление, удаление и переключение меняют данные

Добавление, удаление и переключение `done` MUST менять массив задач. Список и итоги MUST перерисовываться из этого массива, а не правкой отдельных элементов разметки.

#### Scenario: Добавление корректной задачи
- **WHEN** введено название «Конспект» и часы 1,5, и нажата кнопка «Добавить»
- **THEN** в данных появляется задача `title="Конспект"`, `hours=1.5`, `done=false`, и общая сумма часов растет на 1,5

#### Scenario: Удаление задачи
- **WHEN** удалена задача «Повторение» из стартового примера
- **THEN** ее нет в данных и в списке, всего 6 ч, выполнено 2 ч, прогресс 33%

#### Scenario: Отметка «Практики» как готовой
- **WHEN** «Практика» отмечена готовой
- **THEN** у нее `done=true`, выполнено 6 из 8 ч, прогресс 75%

#### Scenario: Повторное переключение
- **WHEN** «Практика» отмечена готовой, а затем отметка снята
- **THEN** у нее снова `done=false`, выполнено 2 из 8 ч, прогресс 25%

### Requirement: Проверка ввода

Название MUST быть непустым после `trim`.
Часы MUST быть числом в диапазоне от 0,5 до 24 включительно с шагом 0,5.
Пустое поле часов MUST считаться ошибкой, а не нулем.
При ошибке задача MUST NOT добавляться, текст ошибки MUST показываться рядом с соответствующим полем, введенные значения MUST оставаться в форме.

#### Scenario: Пустое название
- **WHEN** название пустое или состоит только из пробелов, часы равны 2, и нажата кнопка «Добавить»
- **THEN** задача не добавляется, рядом с полем названия видна ошибка, значение часов осталось в форме

#### Scenario: Пустые часы
- **WHEN** название «Тест», поле часов пустое, и нажата кнопка «Добавить»
- **THEN** задача не добавляется, рядом с полем часов видна ошибка, название осталось в форме

#### Scenario: Отрицательные часы
- **WHEN** название «Тест», часы −1, и нажата кнопка «Добавить»
- **THEN** задача не добавляется, рядом с полем часов видна ошибка, введенные значения остались в форме

#### Scenario: Часы вне диапазона или не кратны 0,5
- **WHEN** часы равны 0, 24,5 или 1,3
- **THEN** задача не добавляется, рядом с полем часов видна ошибка

#### Scenario: Граничные значения часов
- **WHEN** часы равны 0,5 или 24, название непустое
- **THEN** задача добавляется

### Requirement: Расчет прогресса

Прогресс MUST равняться `округление(100 × сумма hours задач с done=true / сумма hours всех задач)`.
Если задач нет, прогресс MUST быть 0%. Значения NaN и Infinity MUST NOT появляться ни в данных, ни в интерфейсе.

#### Scenario: Все задачи удалены
- **WHEN** удалены все задачи
- **THEN** итог 0 ч, выполнено 0 ч, прогресс 0%, на экране нет NaN и Infinity

### Requirement: Фильтр влияет только на видимый список

Фильтр MUST менять только набор видимых задач. Общая сумма часов, сумма выполненных часов и прогресс MUST считаться по всем задачам независимо от фильтра.

#### Scenario: Фильтр «активные»
- **WHEN** на стартовом примере включен фильтр «активные»
- **THEN** в списке видны только «Практика» и «Повторение», «Чтение» скрыто, всего по-прежнему 8 ч, выполнено 2 ч, прогресс остается 25%

#### Scenario: Возврат к полному списку
- **WHEN** после фильтра «активные» выбран фильтр «все»
- **THEN** снова видны все три задачи, итоги не изменились

### Requirement: Узкий экран и подписи

Интерфейс MUST читаться на ширине 390 px без горизонтального скролла.
У каждого поля ввода MUST быть видимая подпись, связанная с полем. У каждой кнопки и переключателя MUST быть понятное текстовое имя.

#### Scenario: Ширина 390 px
- **WHEN** страница открыта в окне шириной 390 px, в том числе с длинным названием задачи
- **THEN** горизонтального скролла нет, текст и элементы управления не обрезаются

#### Scenario: Подписи элементов
- **WHEN** проверяются поля, кнопки и переключатели
- **THEN** у полей названия и часов есть `label`, у кнопок удаления и переключателей выполнения в имени указано, к какой задаче они относятся

### Requirement: Сохранение в localStorage (необязательное улучшение)

Если улучшение реализовано, трекер MUST сохранять массив задач в localStorage после каждого изменения и загружать его при старте.
Если хранилище недоступно или при работе с ним возникает исключение, трекер MUST показать понятное сообщение и MUST продолжить работу с данными в памяти.
Сохраненный пустой список MUST загружаться как пустой и MUST NOT подменяться стартовым примером.

#### Scenario: Восстановление после перезапуска
- **WHEN** «Практика» отмечена готовой и страница перезагружена при доступном хранилище
- **THEN** «Практика» по-прежнему выполнена, прогресс 75%

#### Scenario: Хранилище недоступно
- **WHEN** чтение или запись в localStorage вызывает исключение
- **THEN** видно сообщение, что изменения сохранятся только до закрытия страницы, а добавление, удаление, переключение и фильтр продолжают работать
````

### design.md

````markdown
# Design: add-weekly-tracker

## Context

Автономный трекер учебных задач на неделю. Ни сети, ни CDN, ни внешних библиотек, ни API-ключей. Два варианта поставки: A — один `tracker-v2.html`; B — `index.html`, `styles.css`, `app.mjs`, `domain.mjs`, `tests/acceptance.test.mjs`.

## Goals / Non-Goals

**Goals:** корректные данные и расчеты, проверка ввода с ошибкой у поля, фильтр без влияния на итоги, читаемость на 390 px, необязательное сохранение.
**Non-Goals:** все, что перечислено в Non-Goals в proposal.md.

## Данные

Состояние приложения:

- `tasks`: массив объектов `{ id: string, title: string, hours: number, done: boolean }`.
- `filter`: `"all"` или `"active"`. В интерфейсе подписи «все» и «активные».
- `nextId`: счетчик для новых `id`. При старте он равен максимальному числовому `id` в списке плюс 1. `crypto.randomUUID` не используется, потому что на `file://` он может быть недоступен.
- `storageAvailable`: логическое значение, нужно только для необязательного улучшения.

Стартовый пример:

- `{ id: "1", title: "Чтение", hours: 2, done: true }`
- `{ id: "2", title: "Практика", hours: 4, done: false }`
- `{ id: "3", title: "Повторение", hours: 2, done: false }`

## Доменные функции

Все функции чистые: не трогают DOM и хранилище и не меняют входной массив, а возвращают новый. В варианте B они лежат в `domain.mjs` и экспортируются. В варианте A это тот же код внутри `<script>`.

- `validateInput(titleRaw, hoursRaw)` возвращает `{ ok, errors: { title?, hours? }, value? }`.
  - `title = titleRaw.trim()`. Пустая строка дает ошибку «Введите название».
  - `hoursRaw` приводится к строке и обрезается. Пустая строка дает ошибку «Укажите часы» и до `Number()` не доходит, поэтому пустое значение никогда не становится нулем.
  - Запятая заменяется точкой, затем выполняется `Number(...)`. Ошибкой считаются: `!Number.isFinite(h)`, `h < 0.5`, `h > 24`, `!Number.isInteger(h * 2)`. Текст ошибки: «Часы: число от 0,5 до 24 с шагом 0,5».
- `addTask(tasks, input, id)` возвращает новый массив с задачей `done=false`. Перед добавлением вызывает `validateInput` и при ошибке массив не меняет.
- `removeTask(tasks, id)` возвращает массив без задачи с этим `id`.
- `toggleTask(tasks, id)` возвращает массив, в котором у задачи с этим `id` инвертирован `done`.
- `visibleTasks(tasks, filter)` для `"all"` возвращает все задачи, для `"active"` — задачи с `done=false`.
- `summarize(tasks)` возвращает `{ totalHours, doneHours, progress }`.

## Расчеты

- `totalHours` — сумма `hours` по всем задачам.
- `doneHours` — сумма `hours` по задачам с `done=true`.
- `progress = totalHours === 0 ? 0 : Math.round(100 * doneHours / totalHours)`.
- `summarize` всегда получает полный массив `tasks` и никогда не получает результат `visibleTasks`. Поэтому фильтр на итоги не влияет.
- Все `hours` кратны 0,5, а такие числа и их суммы в двоичной плавающей точке представляются точно. Накопленной ошибки округления не будет.
- Контрольные значения: старт — 8 / 2 / 25%; «Практика» готова — 8 / 6 / 75%; без «Повторения» — 6 / 2 / 33%; пустой список — 0 / 0 / 0%.
- Числа выводятся через `toLocaleString("ru-RU")`, например «2,5 ч».

## Интерфейс

- Один поток отрисовки: любое действие меняет `tasks` или `filter`, затем вызывается `render()`. Он строит список из `visibleTasks(tasks, filter)` и итоги из `summarize(tasks)`.
- Форма: поле «Название» (`<label for>`), поле «Часы» (`type="number"`, `min="0.5"`, `max="24"`, `step="0.5"`, `<label for>`), кнопка «Добавить». У формы стоит `novalidate`, чтобы проверка шла через `validateInput` и ошибка всегда была в нашем элементе рядом с полем.
- Ошибка выводится в элемент под полем. Поле получает `aria-invalid="true"` и `aria-describedby`, ссылающийся на ошибку. При ошибке значения полей не сбрасываются. После успешного добавления форма очищается, а ошибки скрываются.
- Строка задачи: чекбокс выполнения с именем вида «Выполнено: Практика», название, часы, кнопка «Удалить» с `aria-label` вида «Удалить: Практика».
- Фильтр: группа радиокнопок «все» / «активные» с общей подписью «Показать».
- Итоги: «Всего: 8 ч», «Выполнено: 2 ч», «Прогресс: 25%». Дополнительно можно добавить `<progress>` с тем же значением.
- Узкий экран: `<meta name="viewport" content="width=device-width, initial-scale=1">`, `box-sizing: border-box`, никаких фиксированных ширин больше экрана, `flex-wrap` в строках, `overflow-wrap: anywhere` для длинных названий, поля шириной `100%`.

## Хранилище (необязательное улучшение)

- Ключ: `weekly-tracker.tasks.v1`. Значение: JSON-массив задач.
- Загрузка: внутри `try` выполняются `localStorage.getItem` и `JSON.parse`. Значение `null` означает, что данных нет, и тогда загружается стартовый пример. Пустой массив загружается как пустой. Если данные испорчены или не проходят проверку полей, показывается сообщение и загружается стартовый пример.
- Запись после каждого изменения выполняется внутри `try`. При исключении `storageAvailable=false`, выводится сообщение «Хранилище недоступно, изменения сохранятся только до закрытия страницы», дальнейшая работа идет в памяти.
- Ограничение `file://`: поведение localStorage для локальных файлов зависит от браузера. В одних браузерах оно работает, в других хранилище общее для всех локальных файлов, в третьих (а также в приватных режимах) недоступно, выбрасывает исключение или очищается при закрытии. Поэтому сохранение между перезапусками при открытии через `file://` не гарантируется. Трекер обязан работать и без него.

## Решения по вариантам

- **A (`tracker-v2.html`):** все в одном файле, обычный `<script>` без модулей. Открывается напрямую через `file://`.
- **B (модули):** `app.mjs` импортирует `domain.mjs`. Браузеры обычно блокируют загрузку ES-модулей со страницы, открытой через `file://`, поэтому для B нужен локальный статический сервер, например `python3 -m http.server`. Это не внешняя библиотека.
- **Тесты B:** `tests/acceptance.test.mjs` использует встроенные `node:test` и `node:assert` и импортирует только `domain.mjs`. Запуск: `node --test tests/`. Тесты покрывают логику и расчеты. Ширину 390 px, подписи и видимость ошибки у поля они не проверяют, это ручные проверки.

## Risks / Trade-offs

- Через `file://` вариант B без сервера не запустится, а сохранение может не работать. Это ограничение описывается в README или в отчете, а не обходится.
- `type="number"` в разных браузерах по-разному обрабатывает запятую и нечисловой ввод: недопустимый ввод может прийти как пустая строка. В этом случае показывается ошибка «Укажите часы», что безопасно, потому что задача не добавляется.
- Для варианта A отдельных автотестов нет. Его логика проверяется вручную по тем же сценариям или копией доменных функций.
````
